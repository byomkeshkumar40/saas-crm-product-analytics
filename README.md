# SaaS CRM Product Usage & Feature Adoption Analysis

An end-to-end product-analytics portfolio project: synthetic CRM data → SQLite → SQL KPI analysis → Power BI-ready
model → product recommendations. **All data is synthetic** (generated with a fixed seed); no real customers are involved.

## 1. Business Problem
A B2B SaaS CRM company wants to know how customers use the product: how many users are active, which features
matter, whether new accounts activate and adopt automation, which segments are disengaged, and what the product
team should fix first.

## 2. Project Objectives
1. Measure DAU, MAU and DAU/MAU. 2. Rank CRM features by usage. 3. Measure account activation.
4. Compare feature adoption across plan, industry, size and tenure. 5. Check whether newly onboarded users adopt
automation. 6. Find low-engagement segments and inactive accounts. 7. Recommend and prioritise product improvements.

## 3. Dataset Description
Generated by [`scripts/generate_data.py`](scripts/generate_data.py) (`random.Random(42)`, standard library only).
Observation window: **2026-01-01 → 2026-03-31 (90 days)**.

| Table | Rows | Notes |
|---|---|---|
| accounts | 1,200 | 28% signed up inside the window, the rest in 2024–2025 |
| users | 6,331 | 2–14 per account depending on company size |
| events | 76,207 | six CRM features, 18 event names, sessions |
| subscriptions | 1,288 | upgrade history for ~15% of accounts |

Built-in behaviour (not tuned to hit any target KPI): lognormal account engagement scaled by plan and industry;
~10% low-touch accounts; ~28% "drive-by" users who show an onboarding burst then rarely return; per-account feature
adoption dates (advanced features later or never); lower advanced-feature use in an account's first 90 days;
weekday/weekend seasonality; ~8% of accounts churn.

## 4. Tools Used
Python 3 · SQLite · SQL (CTEs, window functions) · pandas · Streamlit · Plotly · Excel (openpyxl) · Git/GitHub. (Power BI-ready tables and DAX are included but no Power BI dashboard was built.)

## 5. Database Schema
Defined in [`sql/schema.sql`](sql/schema.sql) with PK/FK/CHECK constraints and indexes.

```
accounts(account_id PK, signup_date, industry, company_size, subscription_plan, region)
users(user_id PK, account_id FK→accounts, created_at, user_role)
subscriptions(subscription_id PK, account_id FK→accounts, plan, subscription_start, subscription_status)
events(event_id PK, user_id FK→users, account_id FK→accounts, event_timestamp, event_name, feature_name, session_id)
analysis_params(obs_start, obs_end)      -- the 90-day window
v_account_stats                          -- per-account roll-up view used by segment queries
```

## 6. KPI Definitions
Full table with numerators and denominators: [`reports/kpi_definitions.md`](reports/kpi_definitions.md). Highlights:
* **Active** = ≥ 1 event. **DAU** = distinct users per day; **MAU** = distinct users per calendar month.
* **Activation** (account): of accounts that signed up in the window with ≥ 14 observed days, the share with ≥ 2 users
  **and** ≥ 3 features in their first 14 days.
* **Adoption** is reported at **account level** (÷ active accounts) and **user level** (÷ active users), never mixed.

## 7. SQL Analysis
[`sql/product_analysis.sql`](sql/product_analysis.sql) holds 16 analysis queries plus 3 Power BI model queries, each
marked with `-- name:`.

| Query | Metric |
|---|---|
| q01 / q02 / q03 | DAU (with 7-day average) / MAU / DAU÷MAU |
| q04 | Account activation rate (overall, by plan, size, industry) |
| q05 / q06 | Feature adoption (account & user level) / usage frequency |
| q07 | New vs established accounts, fixed 30-day exposure |
| q08 / q08b | Engagement by plan / feature × plan |
| q09 / q09b | Engagement by industry / company size |
| q10 / q10b | Inactive-account list / summary |
| q11 / q11b | New-user automation adoption / all features |

### Dashboard features
* **Product Overview:** total accounts, total users, active users/accounts, average DAU, MAU, DAU/MAU, activation rate;
  DAU trend with 7-day average, MAU by month, activation by plan, active vs not-active users by plan.
* **Feature Adoption:** account- and user-level adoption by feature, usage frequency, Workflow Automation cards,
  new vs established comparison, feature adoption and event mix by subscription plan.
* **Customer Engagement:** inactive accounts, inactivity by plan (Starter vs Enterprise) and company size, engagement by
  industry and company size (switchable metric), engagement trend, downloadable inactive-account list.
* **Sidebar filters:** subscription plan, industry, company size, date range. Each page says which metrics each filter
  affects; fixed-definition metrics (activation, new vs established, inactivity) ignore the date range instead of showing
  misleading numbers. Full table: [`dashboards/streamlit/README.md`](dashboards/streamlit/README.md).

### Dashboard validation
`python dashboards/streamlit/validate_app.py` → 410 checks (saved in
[`validation_results.txt`](dashboards/streamlit/validation_results.txt)): metrics vs the SQL result tables, filtered
scopes vs direct SQL, and a headless run of all three pages with filter changes. In addition, the three pages were opened
in a real browser (Streamlit server + built-in browser pane): the KPI cards, charts and values rendered and matched.
Not tested: other browsers, mobile widths, dark mode, and Python/Streamlit versions other than Python 3.14 with Streamlit 1.66, pandas 3.0, Plotly 7.1.

### Known limitations of the dashboard
* Date-range filtering does not apply to activation, new vs established and inactivity (their definitions are fixed).
* MAU and DAU/MAU use the last calendar month inside the range; a partial month is flagged and not comparable to a full one.
* Very narrow filters can leave small bases (e.g. a handful of accounts); the cards show the counts behind every percentage.
* Filters are not shareable by URL, and the dashboard reads a static SQLite file (no live data).

## 9. Key Findings
Details and hypotheses: [`reports/product_insights.md`](reports/product_insights.md).

| KPI | Result |
|---|---|
| Active users, 90 days | 3,575 of 6,331 (56.5%) |
| Avg DAU / March MAU | 169.0 / 2,470 |
| DAU/MAU (Jan / Feb / Mar) | 0.075 / 0.083 / 0.080 |
| Activation rate | 37.7% (103 of 273) |
| Account adoption (÷ active accounts) | Contact 93.4% · Lead 89.8% · Deal 78.0% · Email 55.4% · Reporting 44.8% · Workflow Automation 26.8% |

1. **Advanced features lag.** Workflow Automation: 8.0% of new vs 25.9% of established accounts (30-day window); 8.7% of active new users adopt it within 14 days.
2. **Small/Starter accounts are weakest.** Activation 23.9% (Starter) vs 60.0% (Enterprise); inactive share 36.1% vs 13.1%.
3. **Stickiness is low.** DAU/MAU ≈ 0.08; 43.5% of users never active; weekday DAU 217.7 vs weekend 49.1.

## 10. Product Recommendations
1. Guided first-automation templates in admin onboarding (metric: new-account automation adoption, baseline 8.0%).
2. 14-day activation checklist and assisted onboarding for Starter / 1–10-employee accounts (baseline activation 23.9%).
3. Invited-user journey fixes plus WAU/MAU tracking (baseline: 44.4% of new users active in their first 14 days).

## 11. How to Reproduce the Project
```bash

python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt          # openpyxl (Excel), streamlit, plotly, pandas (dashboard)

python scripts/run_analysis.py           # builds SQLite DB, runs SQL, exports CSV/Excel/Power BI tables

streamlit run dashboards/streamlit/app.py     # launch the dashboard
```

Needs SQLite ≥ 3.25 (window functions). Verified with Python 3.14 and SQLite 3.51.

## 12. Limitations
* **Synthetic data.** The generator encodes plan, tenure and role effects, so findings validate the method and
  pipeline; they are not evidence about real customers.
* Plan and company size are correlated; the tables cannot separate their effects.
* Plan is the *current* plan; mid-window upgrades are not split.
* `subscriptions` has no end date or price, so churn timing and revenue are not analysed, and inactivity is not validated against churn.
* DAU/MAU uses event-based activity only (no logins/page views).
* The Power BI assets (DAX, build guide) were never run in Power BI Desktop; the delivered dashboard is the Streamlit app.
* Activation thresholds (2 users, 3 features, 14 days) are an assumption, not an industry standard.
